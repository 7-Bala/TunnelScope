# EXP-15 — Eight traffic classes, IKE/DH suite variety, AH — PRE-REGISTRATION (2026-09-20, before capture)

Closes PS gaps a) traffic types and DH groups, b) AH, c) traffic-type prediction
(`research/14-PS-VALIDATION.md`). Lab: strongSwan 6.1.0 pair (alice-pq / bob-pq), keyless router
vantage, config `testbed/configs/exp15/` generated by `testbed/scripts/gen_exp15_conf.py`.

## Part A — traffic classes (classifier)
Classes (PS terms; shape models from `testbed/scripts/tgen.py`, not application replays): voip, web,
bulk (file transfer), interactive (SSH-like), video, email (SMTP-shaped), messaging (WhatsApp-shaped),
icmp. Arms: tunnel (AES-GCM-256), tunnel + TFC padding, transport, tunnel AES-CBC-128/SHA-256
(cipher robustness), mux (two classes at once). 4 repetitions × 20 s, fixed-seed shuffled schedule.

| # | Prediction | Falsified if |
|---|---|---|
| P15-1 | Random Forest, leave-one-repetition-out, unpadded tunnel arm: macro-F1 ≥ 0.90 over 8 classes | < 0.90 |
| P15-2 | The new classes are separable: per-class F1 ≥ 0.80 for email, messaging, icmp | any < 0.80 |
| P15-3 | TFC padding does not stop classification (EXP-05 repeated at 8 classes): macro-F1 ≥ 0.80 | < 0.80 |
| P15-4 | Mixed sessions (mux) are answered "uncertain" (abstain or out-of-distribution) in ≥ 80% of sessions, instead of a confident single label | < 80% |
| P15-5 | Calibrated probabilities: expected calibration error ≤ 0.10 on held-out repetitions | > 0.10 |
| P15-6 | A model trained on the GCM arm still reaches macro-F1 ≥ 0.80 on the CBC arm (cipher changes sizes) | < 0.80 (then train on both, and say so) |

## Part B — IKE / DH suite variety
Arms: MODP-1024 (+AES-128/SHA-1), MODP-1536, MODP-3072 (+PFS), MODP-4096 (+PFS, SHA-384), ECP-256
(AES-GCM-128), ECP-384 (+PFS), Curve25519 (ChaCha20-Poly1305 ESP), 3DES/SHA-1/MODP-1024 (legacy),
Curve25519 + ML-KEM-768 hybrid. Prediction P15-7: every arm's IKE suite and DH group is OBSERVED
exactly as swanctl reports (T2), and each weak arm fails the rules that name it.

## Part C — AH
Arms: AH tunnel SHA-256, AH transport SHA-256, AH transport SHA-1, AH tunnel SHA-384, AH transport
SHA-512. Predictions: P15-8 the Docker Desktop kernel negotiates AH (if not, recorded and AH parsing
tested on a synthetic capture instead); P15-9 AH's plaintext next-header gives the mode exactly
(4 → tunnel, 1/6/17 → transport); P15-10 the ICV length gives the integrity family (12 → *-96,
16 → SHA-256-128, 24 → SHA-384-192, 32 → SHA-512-256); P15-11 "AH provides no confidentiality" is
reported for every AH SA.
