# EXP-28 — Config vs wire: does TunnelScope catch a configuration that does not match the traffic, without false alarms? — PRE-REGISTRATION (2026-09-27, before the comparison is built)

Owner, 2026-09-27: roadmap T-121, approved ("go ahead with T-121"). No surveyed tool compares a VPN's
configuration with what its traffic actually shows (research/16 §7). T-120 made configs readable in the wire
findings' own names.

## What gets built (after this file is committed)
`tunnelscope reconcile <pcap> <config>`: for the connection matching the capture (by addresses, or `--conn`),
each field resolves to one of:
- **match** — what the wire shows is within what the config offers;
- **mismatch** — the wire shows something the config does not offer (drift, or the capture is not from this config);
- **not comparable** — the wire cannot see it (UNKNOWN / NOT_OBSERVABLE, e.g. ESP key length, F-05), or the
  field only means something for the other role (e.g. what the initiator offered, when the config is the responder's);
- **not configured** — the config relies on the implementation's default, which TunnelScope does not claim to know.
Fields: IKE version; IKE encryption, integrity, PRF, key-exchange group; initiator's offered groups; RFC 9370
additional key exchange; RFC 8784 PPK; ESP cipher family (T0 sieve set vs the configured cipher); PFS; mode.
The config's role (initiator / responder) comes from its `local_addrs` vs the capture's IKE_SA_INIT sender.

## Data (fixed now; no new captures)
- **Controls:** every lab connection whose capture shares its name (T-120 found 50 initiator-side pairs), plus
  the responder-side configs (`bob`) for the same captures. The configs are the ones that produced the captures.
- **Drift arms:** copies of control configs changed in exactly one field, generated by `analyze.py` with a fixed
  list (saved in `results/`):
  - D1 IKE key-exchange group changed (e.g. modp2048 → ecp384), every control connection;
  - D2 IKE encryption changed (aes256 → aes128, and CBC ↔ GCM), every control connection;
  - D3 ESP cipher changed to another family (e.g. GCM → CBC+HMAC-SHA256), every control connection with ESP traffic;
  - D4 PFS flipped on the rekey captures whose PFS is measurable;
  - D5 PPK added to / removed from the EXP-27 initiator configs;
  - D6 ML-KEM additional key exchange added to classical initiator configs / removed from the ML-KEM ones;
  - **K (honesty arm):** only the ESP key length changed (aes256gcm16 → aes128gcm16): the wire cannot see ESP key
    length (F-05), so this must be "not comparable", never "match" and never "mismatch".

## Hypotheses and bars
- **H1 (no false alarms):** zero `mismatch` across all control pairs (initiator and responder configs).
- **H2 (catches drift):** every D1–D6 change whose field the wire actually shows for that capture is reported as
  `mismatch`; a change whose wire field is UNKNOWN is `not comparable` (counted separately, not a miss).
  Bar: 100% of the observable changes detected.
- **H3 (honesty):** every K arm is `not comparable` for key length and produces no `mismatch`.
- **H4:** no field whose wire finding is UNKNOWN / NOT_OBSERVABLE is ever reported as `match`.

## Not changed during EXP-28
The findings, rules and risk score. `reconcile` is a new, separate command; `crosstier` is unchanged.
